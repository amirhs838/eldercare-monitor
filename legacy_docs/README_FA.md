# پایش وضعیت و حرکت سالمند با پایتون و دوربین

**نسخهٔ آزمایشی مهندسی؛ دستگاه پزشکی یا سامانهٔ ایمنی تأییدشده نیست.**

این پروژه از مدل ازپیش‌آموزش‌دیدهٔ YOLO Pose برای استخراج نقاط بدن، ByteTrack برای رهگیری افراد و قواعد زمانی برای تخمین وضعیت/حرکت استفاده می‌کند. بخش تشخیص فعالیت، مدل آموزش‌دیده روی سالمندان نیست. هیچ عددی برای دقت واقعی آن اندازه‌گیری یا تضمین نشده است.

## قابلیت جدید این نسخه — فقط یک مورد

**هشدار ماندن طولانی روی زمین، حتی اگر لحظهٔ سقوط دیده نشده باشد.** منطق پایتونی `prolonged_floor_lying` با آستانهٔ پیش‌فرض آزمایشی ۳۰ ثانیه اضافه شده است؛ قابلیت پزشکی یا تأیید ناتوانی در برخاستن نیست.

**برای فعال‌شدن باید `floor_polygon` را برای تصویر دوربین خود تعریف کنید.** محدودهٔ خالی به معنی غیرفعال‌بودن این قابلیت است. قطع مشاهده زمان بی‌حرکتی محسوب نمی‌شود؛ هشدار قبلاً صادرشده نیز با ناپدیدشدن فرد خودکار مختومه نمی‌شود. هشدار سقوط قبلی منتظر این تایمر نمی‌ماند.

- راهنمای دقیق، مبنای انتخاب از محصولات مشابه، API و محدودیت‌ها: [FEATURE_FLOOR_LYING_FA.md](FEATURE_FLOOR_LYING_FA.md)
- دموی بدون دوربین و بدون YOLO: `python demo_floor_lying.py`
- راه‌اندازی واقعی: ابتدا `python select_zones.py --source 0 --config config.json`، سپس `python monitor.py --source 0 --config config.json`.
- خروجی فعلاً رویداد، CSV و پیام کنسول است؛ پیامک یا تماس با مراقب ارسال نمی‌شود.

## چه چیزی تشخیص داده می‌شود؟

| خروجی | معنی دقیق |
| --- | --- |
| `standing` | ایستادنِ ظاهری از شکل بدن |
| `sitting` | نشستنِ احتمالی از خمیدگی زانو و جهت ران/تنه |
| `walking` | راه‌رفتن احتمالی از وضعیت ایستاده و حرکت لگن/پاها |
| `lying` | درازکش بودن؛ الزاماً روی زمین نیست |
| `possible_sleep` | بی‌حرکتی طولانی در وضعیت درازکش داخل محدودهٔ تخت؛ **نه تأیید خواب** |
| `unsteady_gait` | الگوی احتمالی تلوتلو خوردن: نوسان جانبی لگن همراه نوسان تنه در چند ثانیه |
| `falling` | نزول سریع بدن که نیاز به بررسی دارد |
| `prolonged_floor_lying` | درازکش‌بودن ممتد در محدودهٔ کف برای مدت تنظیم‌شده؛ نیاز به بررسی حتی بدون مشاهدهٔ سقوط |
| `lying_after_fall` | ادامهٔ وضعیت درازکش پس از رویداد احتمالی سقوط |
| `unknown` | شواهد کافی نیست، وضعیت مبهم است یا فرد دیده نمی‌شود |

رویدادهای مهم در ستون `event`:
- `prolonged_floor_lying`: هشدار یک‌بارهٔ ماندن طولانی روی کف؛ نیاز به بررسی انسانی.
- `floor_lying_ended`: وضعیت نشسته/ایستادهٔ پایدار پس از این هشدار؛ نه تأیید سلامت یا رسیدن کمک.
- `floor_lying_tracking_expired`, `floor_lying_monitor_stopped`: هشدار حل‌نشده هنگام حذف Track یا توقف موتور؛ نیاز به بررسی دستی.
- `rapid_descent`: افت سریع بدن در چند فریم.
- `possible_collapse`: افت خیلی سریع بدن؛ **ممکن است سقوط، شیرجه، نشستن سریع یا خطای بینایی باشد؛ تشخیص غش/بیهوشی نیست**.
- `possible_fall`: نزول سریع و سپس وضعیت افقی پایدار، بیرون از محدودهٔ تخت و، اگر تعریف شده باشد، داخل محدودهٔ کف.
- `descent_unconfirmed`: افت سریع مشاهده شد، اما شواهد بعدی معیار سقوط را کامل نکرد؛ **این رویداد به معنی بی‌خطر بودن نیست**.
- `upright_after_fall`: پس از سقوط احتمالی، وضعیت ایستاده یا نشسته پایدار دیده شده؛ به معنی سلامت پزشکی نیست.
- `tracking_lost`, `no_person_tracked`, `camera_unavailable`, `temporal_sampling_gap`: مشکل در پوشش پایش.

خواب و درازکش بودن می‌توانند در تصویر یکسان باشند. علت پزشکی غش هم از اسکلت دوبعدی قابل تشخیص نیست. برای این دو، دادهٔ اختصاصی، ارزیابی تخصصی و در صورت نیاز حسگر/دستگاه مناسب لازم است. اگر شخص واقعاً بی‌پاسخ یا در خطر است، منتظر خروجی نرم‌افزار نمانید.

## فایل‌های پروژه

- `monitor.py`: ورودی وب‌کم/ویدئو/RTSP، رهگیری، CSV و پیش‌نمایش اختیاری.
- `engine.py`: استخراج ویژگی، منطق زمانی و مدیریت حالت‌ها؛ مستقل از YOLO برای تست.
- `select_zones.py`: تعیین محدودهٔ تخت و کف با کلیک روی تصویر.
- `config.json`: تنظیمات پیش‌فرض قابل تغییر؛ محدوده‌ها ابتدا خالی هستند.
- `requirements.txt`: وابستگی‌ها.
- `tests/`: تست‌های مصنوعی منطق و چهار تست مسیر ویدئو تا CSV با مدل جایگزینِ ساختگی.
- `TESTING.md`: توضیح دقیق محدودهٔ تست‌ها.

## ۱. نصب

پایتون **۳٫۱۱** پیشنهاد می‌شود؛ محدودهٔ پیشنهادی ۳٫۱۰ تا ۳٫۱۲ است.
در ترمینال وارد پوشهٔ پروژه شوید:

```bash
python -m venv .venv
```

فعال‌سازی در ویندوز PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

در ویندوز CMD:

```bat
.venv\Scripts\activate.bat
```

در لینوکس/مک:

```bash
source .venv/bin/activate
```

سپس:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

برای NVIDIA، نسخهٔ مناسب PyTorch/CUDA را بر اساس راهنمای رسمی https://pytorch.org/get-started/locally/ نصب کنید. سپس از `--device 0` استفاده کنید. برای مک سازگار می‌توانید `--device mps` را امتحان کنید؛ پشتیبانی بسته به سخت‌افزار/نسخه متفاوت است.

اولین اجرای مدل ممکن است وزن‌ها را از اینترنت دانلود کند. برای اجرای بدون اینترنت، وزن قابل‌اعتماد `yolo11s-pose.pt` و وابستگی‌ها را از قبل آماده و مسیر وزن را با `--model` بدهید. فایل مدل ناشناس را اجرا نکنید. وابستگی‌ها محدودهٔ نسخه دارند، نه قفل کامل محیط؛ بعد از تأیید محیط خود با `pip freeze` نسخه‌ها را ثبت کنید.

## ۲. اجرای سریع

وب‌کم، با پردازندهٔ مرکزی و نمایش تصویر:

```bash
python monitor.py --source 0 --config config.json --show
```

در صورت کندی CPU مدل کوچک‌تر و تصویر کوچک‌تر را امتحان کنید:

```bash
python monitor.py --source 0 --model yolo11n-pose.pt --imgsz 640 --device cpu --config config.json --show
```

برای سیستم دارای کارت NVIDIA:

```bash
python monitor.py --source 0 --model yolo11s-pose.pt --device 0 --imgsz 960 --config config.json --show
```

تحلیل یک ویدئوی موجود:

```bash
python monitor.py --source "room.mp4" --config config.json --csv "logs/room.csv" --show
```

دوربین شبکه:

```bash
python monitor.py --source "rtsp://USER:PASSWORD@CAMERA_IP:554/STREAM" --config config.json --csv "logs/camera.csv"
```

آدرس نمونهٔ بالا را با آدرس واقعی دوربین جایگزین کنید. رمز در history ترمینال و فهرست پردازش‌ها ممکن است دیده شود؛ از حساب محدود دوربین استفاده کنید و آن را در فایل‌های عمومی قرار ندهید. برنامه عمداً URL دوربین را در لاگ خودش ذخیره نمی‌کند، اما پیام‌های کتابخانه/درایور ممکن است آن را نمایش دهند.

- خروجی پیش‌فرض: `logs/monitor.csv`.
- بدون `--show` پنجره‌ای باز نمی‌شود؛ مناسب سرور است.
- خروج: `Q`، `Esc` در پنجره، یا `Ctrl+C` در ترمینال.
- `--max-seconds 60`: توقف بعد از ۶۰ ثانیه از زمان منبع.
- `--video-fps 25`: فقط در صورت نیاز به FPS جایگزین برای متادیتای ویدئو؛ FPS واقعی ضبط را بدهید.
- `python monitor.py --help`: همهٔ گزینه‌ها.
- `python monitor.py --print-config`: نمایش تنظیمات بدون بارگذاری YOLO.

برنامه پس از قطع دوربین متوقف می‌شود و کد خروج ۲ می‌دهد؛ اتصال مجدد، نگهبان مستقل، ارسال پیامک و تماس اضطراری در این نسخه پیاده‌سازی نشده‌اند. هشدارها در ترمینال و CSV هستند، نه اعلان به مراقب. برای کاربرد عملی باید مسیر هشدار جداگانه، نظارت بر سلامت سرویس و پاسخ انسانی داشته باشید.

## ۳. محدودهٔ تخت و کف را تنظیم کنید

بدون محدودهٔ تخت، `possible_sleep` عمداً غیرفعال است. بدون محدودهٔ کف، محل سقوط فقط بر اساس حرکت تخمین زده می‌شود و ممکن است مبل با زمین اشتباه شود.

```bash
python select_zones.py --source 0 --config config.json
```

برای ویدئو، مثلاً در ثانیهٔ ۱۰:

```bash
python select_zones.py --source "room.mp4" --at 10 --config config.json
```

۱. کلید `B`: انتخاب تخت. با کلیک، گوشه‌های **سطح تخت** را به ترتیب دور محیط مشخص کنید.
۲. کلید `F`: انتخاب کف. بخش قابل‌دیدن کف اتاق را مشخص کنید.
۳. `U`: حذف نقطهٔ آخر، `C`: پاک‌کردن محدودهٔ انتخاب‌شده.
۴. `S`: ذخیره، `Q`: خروج بدون ذخیره.

محدوده‌ها نباید همدیگر را قطع کنند یا شکل خودمتقاطع داشته باشند. ابزار مختصات را کنترل می‌کند اما هم‌پوشانی/خودتقاطع را خودکار اصلاح نمی‌کند. فقط یک چندضلعی برای هر نوع پشتیبانی می‌شود. اگر کف چند بخش جدا دارد یا مبل/تخت داخل ناحیهٔ کف می‌افتد، ناحیهٔ قابل پایش را محدود کنید؛ این نسخه نقشهٔ سه‌بعدی و چندضلعی دارای حفره ندارد.

مختصات در بازهٔ صفر تا یک ذخیره می‌شوند. عضویت ناحیه بر اساس مرکز دوبعدی شانه/لگن است، **نه تماس واقعی بدن با سطح**؛ با افراد و حالت‌های مختلف آن را بررسی کنید. پس از جابه‌جایی دوربین، تغییر زاویه یا کراپ تصویر حتماً دوباره تنظیم کنید.

## ۴. معنی لاگ CSV

ثبت شامل تغییر وضعیت، رویداد و نمونهٔ دوره‌ای پیش‌فرض هر یک ثانیه است؛ نه ذخیرهٔ همهٔ فریم‌ها. فایل موجود فقط اگر ستون‌هایش یکسان باشند ادامه داده می‌شود. هر اجرا `run_id` مستقل دارد و تنظیمات کنار CSV در `run_....json` ذخیره می‌شوند.

ستون‌های اصلی:
- `logged_at_utc`: زمان UTC نوشتن لاگ، **نه لزوماً زمان ضبط تصویر**.
- `source_seconds`: زمان نسبی ویدئو؛ برای دوربین زنده، زمان یکنواخت محلی هنگام دریافت/دیکد فریم.
- `time_basis`: مشخص می‌کند زمان مربوط به ویدئو است یا دریافت زنده.
- `frame_index`: شمارهٔ فریم؛ در ورودی زنده ممکن است فریم‌ها برای کاهش تأخیر کنار گذاشته شوند.
- `track_id`: شناسهٔ موقت رهگیری؛ هویت واقعی نیست و ممکن است عوض یا بین افراد جابه‌جا شود.
- `row_type`: مقدار `state_change`، `sample`، `event` یا `system`.
- `state`: برچسب زمانیِ پایدارشده؛ به جز حالت خطر/ابهام، کمی تأخیر تثبیت دارد.
- `posture`, `activity`: شواهد فعلی وضعیت و حرکت؛ ممکن است در دورهٔ انتقال با `state` فرق کنند.
- `event`, `reason`: رویداد و دلیل/محدودیت آن.
- `pose_quality`: میانگین اطمینان نقاط معتبر شانه/لگن؛ **درصد صحت فعالیت، خواب یا سقوط نیست**.
- `detection_confidence`: امتیاز تشخیص شخص؛ احتمال صحت رویداد نیست.
- `torso_angle_deg`, `knee_angle_deg`: زاویه‌های ظاهری دوبعدی.
- سرعت‌ها با واحد طول تنه در ثانیه و دامنهٔ نوسان با واحد طول تنه ذخیره می‌شوند، نه متر/ثانیه.
- مختصات `bbox_*`: جعبهٔ فرد در پیکسل.
- `processing_fps`: میانگین هموارشدهٔ سرعت استنتاج مدل/رهگیر؛ سرعت کل سامانه یا FPS دریافتی دوربین نیست.

در نبود فرد، `no_person_tracked` ثبت می‌شود؛ این می‌تواند خالی بودن اتاق، انسداد، تاریکی یا خطای مدل باشد. در ردیف‌های سیستمی، اطلاعات شخص خالی است. فایل بعد از هر ردیف flush می‌شود اما در خرابی دیسک/قطع برق تضمین نگهداری کامل نیست. محدودیت حجم/چرخش خودکار لاگ پیاده‌سازی نشده؛ برای اجرای طولانی فضای دیسک و نگهداری داده را مدیریت کنید.

## ۵. دقت را واقعاً چگونه بهتر کنیم؟

۱. **دوربین ثابت**، نور کافی و دید کامل بدن، به‌خصوص شانه، لگن، زانو و پا. زاویهٔ مایل از کنار معمولاً از نمای خیلی بالا برای این قواعد مناسب‌تر است. لرزش/حرکت دوربین می‌تواند به‌عنوان حرکت فرد تفسیر شود.
۲. فرد در تصویر خیلی کوچک نباشد؛ طول تنهٔ کمتر از حد تنظیم‌شده به `unknown` می‌رود. پوشیده‌شدن بدن با پتو و تکیه‌گاه، واکر، ویلچر، مبلمان و نور کم محدودیت جدی‌اند.
۳. در صورت توان سخت‌افزاری مدل بزرگ‌تر مثل `yolo11m-pose.pt` را آزمایش کنید. مدل بزرگ‌تر **لزوماً دقت فعالیت را بهتر نمی‌کند** و اگر نرخ پردازش پایین بیاید ممکن است سقوط از دست برود. به‌عنوان هدف مهندسی، پردازش پیوسته حدود ۱۵ تا ۳۰ فریم/ثانیه را بررسی کنید، نه تضمین کفایت.
۴. برنامه فریم زندهٔ قدیمی را کنار می‌گذارد تا صف انباشته نشود، اما افت FPS همچنان می‌تواند رویداد سریع را پنهان کند. وقفهٔ بیش از `max_gap_s` تاریخچهٔ کوتاه را بازنشانی می‌کند و باید جدی گرفته شود. تأخیر خود دوربین/شبکه قابل حذف کامل نیست.
۵. از محیط واقعی و افراد رضایت‌داده‌شده ویدئوهای متنوع تهیه و برچسب‌گذاری کنید. سقوط خطرناک را با سالمند اجرا نکنید؛ از ویدئوی موجود یا شبیه‌سازی ایمن با افراد آموزش‌دیده و تجهیزات مناسب استفاده کنید.
۶. نمونه‌های منفی سخت را هم داشته باشید: نشستن سریع، برداشتن جسم از زمین، خم‌شدن، رفتن روی تخت، ورزش، تکیه‌دادن، عبور مراقب و انسداد فرد.
۷. آستانه‌ها را روی مجموعهٔ تنظیم بررسی کنید و **نتیجه را روی افراد/اتاق‌ها/ویدئوهای جداگانه** بسنجید؛ فریم‌های یک ویدئو را بین آموزش و آزمون پخش نکنید.
۸. برای تولید محصول دقیق‌تر، طبقه‌بند زمانی آموزش‌دیده روی توالی اسکلت/ویدئو، مانند TCN، ST-GCN یا مدل مشابه، و ارزیابی دامنهٔ واقعی لازم است. این پروژه چنین طبقه‌بند آموزش‌دیده‌ای ندارد و آموزش YOLO Pose به‌تنهایی به آن «غش» یا «خواب» یاد نمی‌دهد.

معیارهای پیشنهادی برای ارزیابی خارجی: Precision/Recall/F1 هر فعالیت، نرخ سقوط‌های ازدست‌رفته، هشدار کاذب در هر ساعت پایش، تأخیر هشدار از شروع سقوط و درصد زمان `unknown`/قطع پوشش. برای رویدادها، چند ردیف یک رویداد را چند تشخیص مستقل نشمارید. این پروژه ابزار محاسبهٔ این معیارها از برچسب انسانی را شامل نمی‌شود.

پیش‌فرض‌ها نقطهٔ شروع هستند. تلوتلو خوردن با راه‌رفتن عادی، حرکت عمدی یا جابه‌جایی دوربین ممکن است اشتباه شود. سقوط رو به دوربین، فرورفتن روی صندلی، افتادن پشت مانع یا غش بدون افتادن ممکن است تشخیص داده نشود. ورود شخصِ ازقبل روی زمین به تصویر فقط `lying` می‌دهد، چون شواهد خود رویداد سقوط موجود نیست.

## ۶. تست‌ها و عیب‌یابی

تست‌های هسته فقط به NumPy نیاز دارند؛ تست مسیر ویدئو به OpenCV هم نیاز دارد. تست‌ها YOLO واقعی را اجرا نمی‌کنند:

```bash
python -m unittest discover -s tests -v
```

- خطای وزن/دانلود: دسترسی اینترنت یا مسیر وزن محلی را بررسی کنید.
- `unknown` زیاد: نور، پوشش بدن، اندازهٔ شخص، زاویه و وضوح تصویر را بررسی کنید. پایین آوردن شدید حد اطمینان راه‌حل قابل‌اعتماد نیست.
- خواب گزارش نمی‌شود: محدودهٔ تخت لازم است و فرد باید پیوسته بی‌حرکت باشد؛ زمان پیش‌فرض ۱۸۰ ثانیه است.
- هشدار کاذب سقوط: محدودهٔ کف/تخت و نمونه‌های نشستن/درازکشیدن سریع را بررسی کنید؛ آستانه‌ها را با داده تنظیم کنید، نه بر اساس یک کلیپ.
- پنجره باز نمی‌شود: روی دسکتاپ اجرا کنید یا `--show` را بردارید. ابزار انتخاب محدوده به نمایشگر نیاز دارد.
- دوربین باز نمی‌شود: شمارهٔ دوربین، مجوز سیستم‌عامل، اشغال بودن آن و URL/پشتیبانی FFmpeg را بررسی کنید.

## حریم خصوصی، بهره‌برداری و مجوزها

پردازش فریم‌ها در همین برنامه محلی است و کد ویدئو/تصویر ذخیره یا برای تحلیل به سرویس ابری ارسال نمی‌کند. دانلود مدل، قابلیت‌های جانبی/تنظیمات تله‌متری وابستگی‌ها و جریان دوربین شبکه را جداگانه بررسی کنید؛ برای الزام سخت‌گیرانهٔ آفلاین، وزن‌ها را از قبل تهیه و خروجی شبکه را در محیط استقرار محدود کنید. CSV همچنان دادهٔ رفتاری حساس است: رضایت افراد، کنترل دسترسی، نگهداری محدود و امنیت دستگاه لازم‌اند.

کد همهٔ افراد قابل رهگیری را پردازش می‌کند؛ سالمند را از روی سن یا چهره تشخیص نمی‌دهد. وجود چند نفر و قطع/وصل دید می‌تواند شناسه‌ها را عوض کند. شناسهٔ یک اجرا را هویت ثابت بین اجراها ندانید.

مجوز Ultralytics و وزن‌ها را برای استفادهٔ تجاری/بسته بررسی کنید؛ شرایط AGPL-3.0 یا مجوز Enterprise ممکن است بر نحوهٔ توزیع و استفادهٔ شما اثر بگذارد. این بسته هیچ مجوز اختصاصی برای وزن‌ها یا وابستگی‌ها اعطا نمی‌کند.
