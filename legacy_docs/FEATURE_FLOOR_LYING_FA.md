# تنها قابلیت جدید: هشدار ماندن طولانی روی زمین

## انتخاب برای این موتور

نسخهٔ ورودی از قبل افت سریع، سقوط احتمالی، وضعیت درازکش پس از سقوط، احتمال خواب روی تخت و نوسان راه‌رفتن را داشت. شکاف انتخاب‌شده: اگر لحظهٔ سقوط دیده نشود، یا فرد آرام روی زمین افتاده باشد، مسیر مبتنی بر افت سریع فعال نمی‌شود. این قابلیت مستقلاً درازکش‌بودن طولانی در محدودهٔ کالیبره‌شدهٔ کف را برای بررسی فوری علامت می‌زند. «ناتوانی در بلندشدن»، بیهوشی یا علت پزشکی را تشخیص نمی‌دهد.

این تنها قابلیت محصولی اضافه‌شده است؛ داشبورد، تشخیص بیماری، سنسور جدید یا سرویس ارسال پیام اضافه نشده. منطق جدید با پایتون نوشته شده و وابستگی جدید ندارد. مدل Pose قبلی تغییر نکرده است.

## مبنای انتخاب و محصولات مشابه

صفحات رسمی بررسی‌شده در ۸ سپتامبر ۲۰۲۶:

- Vayyar Care: تشخیص و تأیید سقوط و ارسال هشدار از مسیرهای فراخوان پرستار؛ تأکید بر جلوگیری از ماندن طولانی روی زمین. https://vayyar.com/care-pages/why/
- Nobi: تشخیص سقوط و اطلاع به مراقب، نورپردازی پیشگیرانه و بینش از فعالیت روزانه. https://nobi.life/
- Lifeline: تشخیص خودکار سقوط و ارتباط با مرکز پاسخ‌گویی، حتی وقتی کاربر نمی‌تواند دکمه را فشار دهد. https://www.lifeline.com/medical-alert-systems/fall-detection

وجه مشترک مرتبط، شناسایی نیاز به کمک بدون وابستگی به اقدام سالمند است. انتخاب «ماندن طولانی روی زمین بدون مشاهدهٔ سقوط» تصمیم مهندسی برای شکاف این کد است، نه ادعای کپی الگوریتم شرکت‌ها. صفحات محصول، شواهد اعتبارسنجی این پیاده‌سازی نیستند. اعداد تبلیغاتی دقت و زمان پاسخ به این موتور نسبت داده نشده‌اند. این موتور ارتباط واقعی با مراقب برقرار نمی‌کند؛ فقط رویداد و هشدار محلی تولید می‌کند.

## قاعدهٔ دقیق

۱. اسکلت معتبر و زمان منبعِ صعودی دریافت شود.
۲. وضعیت تنه و نسبت کادر، معیار درازکش‌بودن قبلی را داشته باشند.
۳. مرکز تنه در `floor_polygon` باشد و در `bed_polygon` نباشد. محدودهٔ تخت اولویت دارد.
۴. این شواهد به مدت `floor_lying_alert_s` ادامه یابد؛ پیش‌فرض **۳۰ ثانیه** است. این عدد صرفاً پیش‌فرض آزمایشی مهندسی است، نه زمان امن انتظار یا آستانهٔ پزشکی.
۵. رویداد `prolonged_floor_lying` یک‌بار صادر شود. حالت آن هم، مادامی که شواهد درازکش‌بودن روی کف برقرار است، همین نام را دارد.

بی‌حرکتی شرط نیست: حرکت دست یا تلاش برای برخاستن نباید تایمر را صرفاً به خاطر حرکت صفر کند. این قابلیت ممکن است ورزش یا درازکشیدن عمدی روی کف را هم علامت بزند؛ نام هشدار تشخیص سقوط قطعی نیست.

هشدارهای قبلی `possible_fall` و `possible_collapse` منتظر این ۳۰ ثانیه نمی‌مانند و مسیر قبلی خود را دارند.

## قطع مشاهده و پایان رخداد

- نبود Pose، گم‌شدن فرد، شکاف زمانی بزرگ‌تر از `max_gap_s` یا مبهم‌شدن وضعیت، تایمر شواهدِ در انتظار را صفر می‌کند. زمان غیبت هرگز زمان مشاهدهٔ درازکش‌بودن محسوب نمی‌شود.
- اگر هشدار قبلاً صادر شده، غیبت یا رفتن از محدوده آن را به معنی سلامت پاک نمی‌کند. `floor_lying_alert_active` فعال می‌ماند و دلیل `floor_lying_alert_unresolved` ثبت می‌شود. حالت عمومی در غیبت `unknown` است.
- دیدن ایستادن یا نشستن پایدار به مدت `recovery_s` (پیش‌فرض ۲ ثانیه) رویداد `floor_lying_ended` می‌سازد و موتور را برای دورهٔ بعد آماده می‌کند. حتی نشستن روی زمین می‌تواند این شرط تصویری را داشته باشد؛ بنابراین این رویداد **تأیید سلامت یا رسیدن کمک نیست** و نباید خودکار یک پروندهٔ مراقبتی را ببندد.
- با حذف Track پس از TTL، رویداد `floor_lying_tracking_expired` با علامت بررسی دستی ثبت می‌شود؛ در توقف موتور نیز Trackهای هشدار‌دار `floor_lying_monitor_stopped` ثبت می‌کنند. این‌ها وضعیت همان قابلیت‌اند، نه قابلیت‌های تشخیص جدید.
- حافظهٔ هشدار محدود به Track و اجرای فعلی است. تغییر شناسه، راه‌اندازی مجدد یا توقف ناگهانی پردازش می‌تواند حافظه را از بین ببرد؛ CSV تاریخچه است، نه مدیر رخداد پایدار. تطبیق هویت بین دوربین‌ها یا بازیابی هشدار پس از restart پیاده‌سازی نشده است. مصرف‌کنندهٔ بیرونی باید رخداد باز را با گم‌شدن Track یا نبود داده، مختومه فرض نکند.

## راه‌اندازی با دوربین یا ویدئو

از پوشهٔ پروژه:

```bash
python -m pip install -r requirements.txt
python select_zones.py --source 0 --config config.json
python monitor.py --source 0 --config config.json --csv logs/monitor_floor.csv
```

در ابزار انتخاب محدوده، `F` برای کف، `B` برای سطح تخت و `S` برای ذخیره است. فقط کف قابل‌مشاهده را مشخص کنید؛ تخت و مبل را داخل کف قرار ندهید. برای ویدئو، در هر دو دستور به جای `0` مسیر ویدئو را قرار دهید. اگر دوربین جابه‌جا یا تصویر crop شد، دوباره کالیبره کنید. روی محیط بدون نمایشگر، رأس‌های نرمال‌شدهٔ همان تصویر باید به صورت دستی تنظیم شوند.

تنها پارامتر جدید در `config.json`:

```json
"floor_lying_alert_s": 30.0
```

این یک فیلد داخل JSON موجود است، نه فایل تنظیمات کامل. `floor_polygon` عمداً خالی تحویل داده می‌شود چون محدودهٔ اتاق شما را نداریم. **بدون تعریف کف، قابلیت جدید غیرفعال است** و برنامه هنگام شروع این موضوع را اعلام می‌کند. پیکربندی‌های قدیمی نیز بارگذاری می‌شوند و آستانهٔ جدید مقدار پیش‌فرض می‌گیرد.

## API موتور

همان مسیر قبلی حفظ شده است:

```python
from engine import Config, TemporalMonitor, extract_feature

cfg = Config.load("config.json")
monitor = TemporalMonitor(cfg)  # برای هر Track یک نمونهٔ جدا
feature = extract_feature(t, keypoints, bbox, (width, height), cfg)
decision = monitor.update(feature) if feature is not None else monitor.missing(t)

if "prolonged_floor_lying" in decision.events:
    print("بررسی فوری وضعیت سالمند لازم است")

active = decision.floor_lying_alert_active
observed_seconds = decision.floor_lying_observed_s
```

`t` زمان صعودی منبع است؛ برای ویدئو زمان ویدئو، نه مدت صرف‌شده برای inference. `keypoints` آرایهٔ COCO-17 با شکل `(17, 3)` و `bbox` چهار مختصات پیکسلی است. مثال API متغیرهای ورودی دوربین را از فراخواننده می‌گیرد. برای اجرای بدون دوربین، `demo_floor_lying.py` را اجرا کنید.

`floor_lying_observed_s` فقط طول دنبالهٔ فعلی مشاهدهٔ معتبر را می‌گوید، نه کل زمان حادثه؛ با شکاف صفر می‌شود حتی اگر هشدار قبلی فعال بماند. ستون‌های CSV تغییر نکرده‌اند: مدت مشاهده و وضعیت حل‌نشده در `reason`، نوع رخداد در `event` و حالت در `state` ثبت می‌شود. بنابراین CSVهای قبلی با همان schema همچنان قابل append هستند. مصرف‌کننده‌هایی که نام حالت‌ها را whitelist می‌کنند باید نام جدید را بپذیرند.

## محدودیت‌های ضروری

این منطق دوبعدی و قاعده‌محور است. عضویت مرکز تنه در چندضلعی، تماس واقعی با زمین را ثابت نمی‌کند. زاویهٔ دوربین، پوشیدگی بدن، نور، خطای Pose، چند نفر، مبل یا تخت بدکالیبره و تغییر شناسه می‌توانند هشدار کاذب یا ازدست‌رفتن هشدار بدهند. افتادن در وضعیت غیر‌درازکش یا خارج دید ممکن است تشخیص داده نشود. فقدان هشدار به معنی ایمنی نیست.

قبل از استفادهٔ واقعی باید مدل روی دستگاه هدف و دادهٔ رضایت‌مندانه و برچسب‌خوردهٔ محیط ارزیابی شود، خطای مثبت و منفی سنجیده شود و مسیر قابل‌اتکای رسیدن هشدار به مراقب طراحی شود. برای آزمایش، از سالمند نخواهید سقوط کند. این نسخه جایگزین مراقب یا سامانهٔ تأییدشدهٔ ایمنی نیست.
